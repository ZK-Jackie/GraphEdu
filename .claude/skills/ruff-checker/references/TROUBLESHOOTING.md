# 故障排除指南

## 常见问题处理

### 1. 自动修复失败

#### 问题：语法错误阻止修复

**症状**：
```
error: Failed to parse file
```

**处理流程**：
1. 定位语法错误的具体文件和行号
2. 使用 `ruff check --select F,E --ignore F401 file.py` 只显示语法错误
3. 手动修复语法错误
4. 重新运行自动修复

**询问用户**：
- 是否需要显示完整错误信息？
- 是否需要尝试自动修复语法问题？

#### 问题：上下文复杂的修复

**症状**：
修复后代码行为改变或引入新错误

**处理流程**：
1. 回滚修改：`git checkout file.py`
2. 显示原始问题和建议修复
3. 使用 `AskUserQuestion` 询问用户偏好：
   - 手动修复
   - 忽略该问题
   - 添加 `# noqa` 注释

#### 问题：多文件依赖问题

**症状**：
修复一个文件导致其他文件报错

**处理流程**：
1. 识别受影响的文件列表
2. 显示影响范围
3. 询问用户是否：
   - 全局修复（运行 `ruff check --fix .`）
   - 逐文件修复
   - 跳过跨文件修复

### 2. 配置问题

#### 问题：找不到配置文件

**症状**：
```
warning: No configured rule set (e.g., `select`).
```

**处理流程**：
1. 检查是否存在 `pyproject.toml` 或 `ruff.toml`
2. 如果不存在，询问用户是否创建默认配置
3. 推荐配置基于项目标准：

```toml
[tool.ruff]
line-length = 88
target-version = "py311"

[tool.ruff.lint]
select = ["F", "E", "W", "I"]
ignore = ["F401"]
```

#### 问题：规则冲突

**症状**：
不同规则产生冲突的修复建议

**处理流程**：
1. 识别冲突规则
2. 显示冲突内容
3. 询问用户优先级：
   - 优先格式化（E, W）
   - 优先质量检查（PLR, PERF）
   - 自定义规则优先级

### 3. 性能问题

#### 问题：检查速度慢

**症状**：
大型项目中 ruff 运行时间长

**处理流程**：
1. 使用缓存加速（ruff 默认启用）
2. 限制检查范围：只检查变更文件
3. 并行运行：`ruff check --jobs N`（N = CPU 核心数）

**询问用户**：
- 是否只检查 git 变更文件？
- 是否增加并行度？

#### 问题：内存占用高

**症状**：
检查大型文件时内存溢出

**处理流程**：
1. 分批检查文件
2. 排除大型文件或目录
3. 增加 `--max-line-length` 限制快速检查

### 4. 输出解析问题

#### 问题：JSON 输出解析失败

**症状**：
无法正确解析 `ruff check --output-format=json` 输出

**处理流程**：
1. 降级到文本输出：`ruff check --output-format=concise`
2. 手动解析文本输出
3. 检查 ruff 版本是否过旧

#### 问题：位置信息不准确

**症状**：
报错行号与实际不符

**处理流程**：
1. 这是已知问题，可能由于多行语句
2. 使用 `--no-fix` 预览模式查看
3. 结合实际文件内容判断

## 交互式决策流程

### 决策树：是否自动修复？

```
开始
  │
  ├─ 问题类型是什么？
  │   ├─ 格式化（E, W）→ 自动修复
  │   ├─ 导入（F, I）→ 自动修复
  │   ├─ 重构（PLR, PERF）→ 询问用户
  │   ├─ 类型（T, FA）→ 询问用户
  │   └─ 其他 → 检查规则说明
  │
  ├─ 是否可以自动修复？
  │   ├─ 是 → 继续
  │   └─ 否 → 询问用户处理方式
  │
  ├─ 修复前是否需要备份？
  │   ├─ 是 → 创建备份或使用 git
  │   └─ 否 → 直接修复
  │
  └─ 修复后验证
      ├─ 成功 → 完成
      ├─ 失败 → 回滚并询问
      └─ 新问题 → 递归处理
```

## 询问用户模板

### 场景 1: 重构建议

```markdown
发现 ${issue_count} 个重构建议：
- PLR0913: ${file}:${line} - 函数参数过多（${count} 个）
- PER401: ${file}:${line} - 可以使用列表推导

是否应用这些重构？（可能影响代码可读性）
```

### 场景 2: 修复失败

```markdown
自动修复失败：${error_message}

选项：
1. 显示详细信息
2. 手动修复该文件
3. 忽略该问题（添加 # noqa）
4. 跳过并继续
```

### 场景 3: 影响范围

```markdown
此修复将影响 ${file_count} 个文件：
- ${file_list}

是否继续？
```

## 最佳实践

1. **使用 Git**：修复前确保工作区干净，方便回滚
2. **渐进式修复**：先修复安全规则，再处理风险规则
3. **团队协作**：重大修复前与团队确认
4. **保留上下文**：记录修复历史和决策原因
5. **配置优先**：在 `pyproject.toml` 中配置团队标准

# 查看规则详情

# 查看完整规则列表

ruff --version
