# Ruff 规则分类参考

## 规则分类矩阵

### 自动修复（安全）- 无需询问

这些规则的修复是安全的，可以自动应用：

**格式化相关（E、W 系列）**：
- `E` - pycodestyle 错误（大部分）
- `W` - pycodestyle 警告（大部分）
- 示例：E501（行过长）、E303（多余空行）

**导入相关（F、I 系列）**：
- `F401` - 未使用的导入
- `F403` - `from module import *`
- `I` - 导入排序和格式化
- 示例：F401, F403, I001, I002

**简单语法（F 系列）**：
- `F841` - 未使用的局部变量
- `F821` - 未定义的名称
- `F601` - 字典键重复
- 示例：F821, F841, F601, F811

### 需要询问（风险）- 可能有副作用

这些规则的修复可能改变代码行为或影响可读性：

**重构建议（PLR 系列）**：
- `PLR0913` - 参数过多（>5个）
- `PLR0915` - 语句过多
- `PLR2004` - 魔术值
- `PLR0904` - 类中过多公共方法

**性能优化（PERF 系列）**：
- `PERF101` - 不必要的列表复制
- `PERF102` - 不必要的字典投影
- `PERF401` - 使用列表推导替代 for 循环

**类型相关（T、FA 系列）**：
- `T` - 类型相关打印和比较
- `FA` - 未来注解
- 示例：T201, T203, FA102

**复杂重构（RUF 系列）**：
- `RUF017` - 避免字典键查询
- `RUF019` - 不必要的键检查
- `RUF015` - 不必要的列表索引

### 始终询问（高风险）- 可能破坏功能

这些规则的修复需要仔细审查：

**复杂重构**：
- `PLR0912` - 分支过多（复杂控制流）
- `PLR0911` - 返回语句过多
- `C901` - 函数过于复杂

**语义改变**：
- `UP` - 升级语法（可能改变兼容性）
- `PYI` - 存根文件特定规则

## 快速查询指南

### 按严重程度查询

**Error 级别**（必须修复）：
- F8xx, F6xx, E9xx

**Warning 级别**（应该修复）：
- Exxx, Wxxx, PLW

**Info 级别**（建议修复）：
- I, PER, RUF

### 按类别查询

**Pyflakes (F)**: 快速检查，通常安全
**pycodestyle (E, W)**: 代码风格，通常安全
**Pylint (PL)**: 代码质量，需要评估
**isort (I)**: 导入排序，安全
**pyupgrade (UP)**: 语法升级，需要评估
**Ruff-specific (RUF)**: 混合，需要逐个评估

## 使用建议

1. **首次运行**：使用 `--select F,E,W` 进行安全检查
2. **逐步启用**：逐步添加 PLR、PERF、RUF 规则
3. **团队约定**：与团队确定哪些规则需要询问

## 完整规则列表

获取完整规则列表：

```bash
ruff rule --all
```

查看特定规则详情：

```bash
ruff rule F401
```
